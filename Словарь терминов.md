# Словарь терминов (Глоссарий)

## Определения

| Термин | Определение | Формат | Правило верификации | Синоним |
| --- | --- | --- | --- | --- |
| Пользователь | Человек, использующий мессенджер через клиентское приложение для отправки сообщений, управления чатами, профилем, звонками и уведомлениями | Строковый идентификатор пользователя (userId) | Должен быть уникальным в системе, не пустым и совпадать с записью в БД | Участник, Клиент |
| Клиентское приложение | Программный интерфейс на устройстве пользователя, через который он взаимодействует с сервером мессенджера | Мобильное/десктопное приложение | Должно иметь актуальную версию протокола и валидный токен сессии | Клиент |
| Сервер мессенджера | Центральный сервер, обрабатывающий запросы клиента, управляющий сообщениями, чатами, профилем, уведомлениями и звонками | Серверное ПО | Должен быть доступен по сети и иметь доступ к необходимым сервисам и БД | Backend, Сервер |
| Чат | Логическая группа сообщений между одним или несколькими пользователями | Целочисленный или строковый идентификатор (chatId) | Идентификатор чата должен быть уникален; пользователь должен быть участником чата, чтобы отправлять и читать сообщения | Диалог, Группа |
| Сообщение | Текстовая единица общения в рамках чата, может содержать вложения и отметку о редактировании | Уникальный идентификатор (messageId), текст, метаданные | Должно быть связано с существующим чатId и отправителем; не должно нарушать ограничения по размеру и формату | Message |
| Менеджер сообщений | Сервис, отвечающий за создание, валидацию, редактирование и получение сообщений | Сервис/модуль на стороне сервера | Должен проверять права отправителя, корректность данных и обеспечивать целостность записей в БД | MessageManager |
| Сервис доставки | Сервис, отвечающий за доставку сообщений участникам чата и выставление статусов доставки | Сервис/модуль на стороне сервера | Должен корректно обрабатывать список участников и обновлять статусы «доставлено»/«прочитано» | DeliveryService |
| Сервис уведомлений | Сервис, выполняющий отправку системных и push-уведомлений о новых сообщениях, звонках и событиях | Сервис/модуль на стороне сервера | Должен учитывать пользовательские настройки уведомлений и корректно взаимодействовать с push-шлюзом | NotificationService |
| Push-уведомление | Уведомление, отправляемое на устройство пользователя через внешний push-шлюз при новых событиях (сообщения, звонки) | Структурированный payload (заголовок, текст, метаданные) | Должно отправляться только на активные устройства с валидным токеном и с учётом настроек уведомлений | Push, Push-сообщение |
| Push-токен устройства | Уникальный идентификатор устройства, используемый для отправки push-уведомлений | Строка (deviceToken) | Должен быть выдан платформой (APNS/FCM и т.п.), быть валидным и связан с конкретным userId | Device token |
| SMS-шлюз | Внешний или внутренний сервис, используемый для отправки SMS-кодов подтверждения при регистрации и верификации | Внешний API | Должен поддерживать отправку сообщений на указанный номер и возвращать статус доставки | SMS-сервис |
| Сервис профилей | Сервис, отвечающий за хранение и изменение данных профиля пользователя (никнейм, аватар, настройки приватности) | Сервис/модуль на стороне сервера | Должен обеспечивать целостность данных профиля и взаимодействие с кэшем и БД | ProfileService |
| Сервис валидации | Сервис, выполняющий проверки корректности данных (никнейм, аватар, настройки приватности и др.) | Сервис/модуль на стороне сервера | Должен содержать правила валидации и возвращать детализированные ошибки при нарушениях | ValidationService |
| Кэш пользователей | Хранилище часто запрашиваемых данных профилей и настроек, предназначенное для ускорения работы системы | In-memory хранилище (key–value) | Должен синхронизироваться с БД при изменении данных и иметь стратегии инвалидизации | Cache |
| Менеджер чатов | Сервис, отвечающий за создание, изменение, удаление и поиск чатов, а также проверку прав пользователя | Сервис/модуль на стороне сервера | Должен валидировать входные данные и права, корректно обновлять записи в БД чатов | ChatManager |
| База данных | Основное хранилище данных системы: пользователи, чаты, сообщения, настройки, токены и т.п. | Реляционная или документная БД | Должна обеспечивать целостность, уникальность ключей, поддержку транзакций (где требуется) | DB, Хранилище |
| База данных чатов | Специализированная часть базы данных или отдельное хранилище для информации о чатах и их структуре | Таблицы/коллекции с чатами и участниками | Должна гарантировать уникальность chatId и корректную связь чатов с пользователями | ChatDB |
| Никнейм | Отображаемое имя пользователя в системе мессенджера | Строка (3–32 символа) | Должен соответствовать правилам длины, набора символов и быть уникальным в пределах системы | Username, Логин |
| Настройки приватности | Набор параметров, определяющих, кто может видеть профиль, писать в ЛС, добавлять в контакты и т.д. | Структурированный объект (перечисления/флаги) | Значения параметров должны входить в допустимые наборы и не противоречить друг другу | Privacy settings |
| Аватар | Изображение, визуально представляющее пользователя или чат | Файл изображения (URL, blob) | Должен соответствовать ограничениям по размеру, формату и разрешению; может проходить модерацию | Avatar, Фото профиля |
| Настройки уведомлений | Параметры, определяющие режим получения уведомлений (звук, баннеры, mute чатов и т.п.) | Структурированный объект | Значения должны соответствовать поддерживаемым режимам, сохраняться и применяться при отправке уведомлений | Notification settings |
| Звонок | Сеанс голосового или видеосоединения между пользователями в мессенджере | Запись с идентификатором звонка (callId) и метаданными | Должен иметь валидных участников, тип (аудио/видео) и статусы (инициирован, принят, отклонён, завершён) | Call, Вызов |
| Сессия звонка | Техническое представление активного звонка, используемое сервисом звонков для установки медиа-соединения | Объект с callId, участниками, параметрами медиа | Должна создаваться при старте звонка и корректно завершаться с обновлением статуса в БД | Call session |
