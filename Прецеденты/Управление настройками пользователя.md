# Описание прецедента: Управление профилем пользователя

(смена никнейма, настройки приватности, аватар)

## Рамки  
Подсистема управления профилем пользователя в мессенджере.

## Уровень  
Задача, определённая пользователем.

## Основной исполнитель  
Авторизованный пользователь мессенджера.

## Заинтересованные лица и их требования

**Пользователь:**  
- хочет менять свой никнейм и аватар;  
- хочет управлять видимостью профиля и доступностью личных сообщений;  
- хочет получать понятные сообщения об ошибках при неверных настройках.

**Система профилей/валидации:**  
- должна проверять уникальность и корректность никнейма;  
- должна валидировать настройки приватности;  
- должна надёжно хранить и обновлять данные в БД и кэше.

## Предусловия
1. Пользователь авторизован.  
2. Профиль пользователя существует в базе данных.  

## Постусловия
1. Изменённые данные профиля сохранены в БД.  
2. Кэш профиля и настроек актуализирован.  
3. Клиентское приложение отобразило обновлённую информацию.

---

## Основной успешный сценарий: Смена никнейма

1. Пользователь открывает настройки профиля.  
2. Клиент запрашивает текущие настройки у сервера.  
3. Сервер загружает профиль пользователя через сервис профилей.  
4. Пользователь видит форму редактирования никнейма.  
5. Пользователь вводит новый никнейм.  
6. Клиент отправляет запрос `updateUsername(userId, newUsername)` на сервер.  
7. Сервер передаёт никнейм в сервис валидации.  
8. Сервис валидации проверяет длину, допустимые символы и уникальность никнейма.  
9. При успешной проверке профиль обновляется в БД.  
10. Кэш пользователя инвалидируется/обновляется.  
11. Клиент получает подтверждение и показывает сообщение «Никнейм успешно изменён».

### Альтернативные сценарии при смене никнейма

- Никнейм не соответствует правилам — пользователь получает сообщение о нарушении ограничений.  
- Никнейм уже занят — пользователю предлагается выбрать другой.

---

## Основной успешный сценарий: Изменение настроек приватности

1. Пользователь открывает раздел «Настройки приватности».  
2. Клиент запрашивает текущие настройки у сервера.  
3. Сервер загружает их из БД через сервис профилей.  
4. Пользователь меняет параметры приватности (кто видит профиль, кто может писать в ЛС и т.д.).  
5. Клиент отправляет новые настройки на сервер.  
6. Сервис профилей валидирует сочетание настроек.  
7. При корректных настройках данные сохраняются в БД.  
8. Кэш приватности обновляется.  
9. Пользователь видит сообщение «Настройки приватности сохранены».

### Альтернативные сценарии при настройке приватности

- Настройки конфликтуют или некорректны — система сообщает пользователю об ошибке без сохранения изменений.

---

## Основной успешный сценарий: Изменение аватара

1. Пользователь нажимает «Изменить аватар» в профиле.  
2. Клиент предлагает выбрать изображение из камеры или галереи.  
3. Пользователь выбирает фото, клиент обрабатывает и сжимает его.  
4. Клиент отправляет `uploadAvatar(userId, imageData)` на сервер.  
5. Сервис валидации проверяет формат, размер и разрешение изображения.  
6. При успешной валидации новый аватар сохраняется в БД или файловом хранилище.  
7. Кэш аватара обновляется.  
8. Клиент получает URL нового аватара и отображает его пользователю.

### Альтернативный сценарий при изменении аватара

- Изображение не проходит валидацию — пользователь получает сообщение «Некорректное изображение».

---

## Частота использования
Средняя — настройки профиля меняются редко, но регулярно по мере необходимости пользователя.

---

## Открытые вопросы
1. Нужно ли логировать историю изменений никнейма/аватара?  
2. Нужны ли ограничения по частоте изменения никнейма?  
3. Следует ли применять модерацию аватаров (фильтрация запрещённого контента)?

```plantuml
@startuml

actor "Пользователь" as User
participant "Клиентское приложение" as App
participant "Сервер мессенджера" as Server
participant "Менеджер чатов" as ChatManager
participant "База данных чатов" as ChatDB
participant "Сервис уведомлений" as Notifications

== Создание чата ==

User -> App: Нажать "Создать чат"
activate App

App -> User: Показать интерфейс выбора
User --> App: Выбрать контакты и ввести название
App -> Server: createChat(contacts, title, type)
activate Server

Server -> ChatManager: validateAndCreateChat()
activate ChatManager

ChatManager -> ChatManager: Проверить валидность данных
alt Данные невалидны
    ChatManager --> Server: Ошибка: неверные данные
    Server --> App: Ошибка создания чата
    App --> User: Показать сообщение об ошибке
else Данные валидны
    ChatManager -> ChatDB: saveChatInfo()
    activate ChatDB
    ChatDB --> ChatManager: ID созданного чата
    deactivate ChatDB
    
    ChatManager -> Notifications: notifyUsers(chatId, participants)
    activate Notifications
    Notifications --> ChatManager: Уведомления отправлены
    deactivate Notifications
    
    ChatManager --> Server: Chat создан успешно
    Server --> App: Подтверждение создания + chatId
    App --> User: Чат создан, открыть чат
end

deactivate ChatManager
deactivate Server
deactivate App

== Редактирование чата ==

User -> App: Открыть настройки чата
activate App
App -> Server: getChatInfo(chatId)
activate Server
Server -> ChatDB: loadChatInfo(chatId)
activate ChatDB
ChatDB --> Server: Данные чата
Server --> App: Информация о чате
App --> User: Показать форму редактирования

User --> App: Ввести изменения (название, аватар)
App -> Server: updateChat(chatId, changes)
Server -> ChatManager: validateChanges()
activate ChatManager

alt Изменения невалидны
    ChatManager --> Server: Ошибка валидации
    Server --> App: Ошибка обновления
    App --> User: Сообщение об ошибке
else Изменения валидны
    ChatManager -> ChatDB: updateChatInfo()
    ChatDB --> ChatManager: Изменения сохранены
    ChatManager -> Notifications: notifyChatUpdated()
    activate Notifications
    Notifications --> ChatManager: Участники уведомлены
    deactivate Notifications
    ChatManager --> Server: Обновление успешно
    Server --> App: Подтверждение редактирования
    App --> User: Изменения сохранены
end

deactivate ChatManager
deactivate Server
deactivate App

== Удаление чата ==

User -> App: Открыть меню чата → "Удалить"
activate App
App -> User: Показать подтверждение удаления
User --> App: Подтвердить удаление
App -> Server: deleteChat(chatId)
activate Server

Server -> ChatManager: checkDeletePermissions(chatId, userId)
activate ChatManager

alt Нет прав на удаление
    ChatManager --> Server: Ошибка прав
    Server --> App: Отказ в удалении
    App --> User: "Недостаточно прав"
else Есть права на удаление
    ChatManager -> ChatDB: markChatAsDeleted()
    activate ChatDB
    ChatDB --> ChatManager: Чат помечен как удаленный
    deactivate ChatDB
    
    ChatManager -> Notifications: notifyChatDeleted()
    activate Notifications
    Notifications --> ChatManager: Уведомления отправлены
    deactivate Notifications
    
    ChatManager --> Server: Удаление завершено
    Server --> App: Подтверждение удаления
    App --> User: Чат удален, вернуться к списку чатов
end

deactivate ChatManager
deactivate Server
deactivate App

== Поиск чатов ==

User -> App: Ввести поисковый запрос
activate App
App -> Server: searchChats(query, userId)
activate Server

Server -> ChatDB: findChatsByQuery(query, userId)
activate ChatDB

alt Чат(ы) найдены
    ChatDB --> Server: Список чатов
    Server --> App: Результаты поиска
    App --> User: Показать найденные чаты
    
    User -> App: Выбрать чат из результатов
    App -> Server: loadChat(chatId)
    Server -> ChatDB: getChatDetails(chatId)
    ChatDB --> Server: Полная информация о чате
    Server --> App: Данные чата
    App --> User: Открыть выбранный чат
else Чаты не найдены
    ChatDB --> Server: Пустой результат
    Server --> App: Нет результатов
    App --> User: "Чаты не найдены"
end
deactivate ChatDB
deactivate Server
deactivate App

@enduml
```
