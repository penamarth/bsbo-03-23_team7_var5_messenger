# Описание прецедента: Уведомления

## Рамки  
Подсистема уведомлений мессенджера.

## Уровень  
Задача, определённая пользователем.

## Основной исполнитель  
Пользователь мессенджера.

## Заинтересованные лица и их требования

**Пользователь:**  
- хочет своевременно получать уведомления о новых сообщениях;  
- хочет управлять режимами уведомлений (звук, баннеры, mute чата);  
- хочет, чтобы уведомления не приходили, если он их отключил.

**Система мессенджера:**  
- должна корректно сохранять push-токены устройств;  
- должна отправлять уведомления только тем пользователям, у которых включены уведомления;  
- должна корректно управлять настройками для разных устройств.

**Push-шлюз:**  
- ожидает валидные токены и корректные запросы на отправку push-уведомлений.

## Предусловия
1. Пользователь авторизован в приложении.  
2. Мобильное устройство имеет действительный push-токен.  
3. Пользователь ранее не отключил уведомления глобально или для конкретного чата.

## Постусловия
1. Устройство пользователя зарегистрировано на сервере.  
2. Уведомление о новом сообщении доставлено, либо корректно записан статус ошибки доставки.  
3. Изменённые настройки уведомлений сохранены в базе данных.

---

## Основной успешный сценарий

1. Пользователь запускает приложение, система отправляет на сервер `deviceToken`.  
2. Сервер сохраняет токен в базе данных.  
3. Пользователь получает подтверждение, что уведомления включены.  
4. При поступлении нового сообщения сервер вызывает сервис уведомлений.  
5. Сервис уведомлений проверяет настройки пользователя и список активных устройств.  
6. Push-уведомления отправляются через push-шлюз.  
7. Пользователь получает уведомление.  
8. Пользователь может изменить настройки уведомлений в меню приложения.  
9. Сервер сохраняет обновлённые параметры.  
10. Приложение сообщает пользователю об успешном изменении.

---

## Альтернативные сценарии

### Уведомления отключены пользователем
- Система не отправляет push-уведомления.

### Нет активных устройств
- Уведомления не отправляются, статус фиксируется.

### Ошибка push-шлюза
- Система фиксирует ошибку доставки и продолжает работу.

---

## Частота использования
Высокая — используется ежедневно при каждом новом сообщении.

---

## Открытые вопросы
1. Нужно ли хранить историю состояний доставки уведомлений?  
2. Должна ли система уведомлять пользователя о сбое доставки push-сообщения?  
3. Следует ли автоматически удалять `deviceToken`, если уведомления долго не доставляются?

```plantuml
@startuml
actor "Пользователь" as User
participant "Клиентское приложение" as App
participant "Сервер мессенджера" as Server
participant "Сервис уведомлений" as NotificationService
participant "База данных" as DB
participant "Push-шлюз" as PushGateway

== Регистрация устройства для push-уведомлений ==

User -> App: Вход в аккаунт / запуск приложения
activate App
App -> Server: registerDevice(userId, deviceToken, platform)
activate Server

Server -> DB: saveOrUpdateDeviceToken(userId, deviceToken, platform)
activate DB
DB --> Server: Токен сохранён
deactivate DB

Server --> App: deviceRegistered()
App --> User: Уведомления включены
deactivate Server
deactivate App


== Отправка уведомления о новом сообщении ==

Server -> NotificationService: notifyNewMessage(receiverId, chatId, messageId)
activate NotificationService

NotificationService -> DB: getUserNotificationSettings(receiverId)
activate DB
DB --> NotificationService: Настройки уведомлений
deactivate DB

alt Уведомления выключены / чат заглушён
    NotificationService --> Server: notificationsSkipped()
else Уведомления разрешены

    NotificationService -> DB: getActiveDevices(receiverId)
    activate DB
    DB --> NotificationService: Список устройств (deviceToken[])
    deactivate DB

    alt Нет активных устройств
        NotificationService --> Server: noDevicesForNotifications()
    else Есть активные устройства

        loop Для каждого устройства
            NotificationService -> PushGateway: sendPush(deviceToken, payload)
            activate PushGateway

            alt Успешная отправка
                PushGateway --> NotificationService: delivered
            else Ошибка отправки
                PushGateway --> NotificationService: deliveryFailed
            end

            deactivate PushGateway
        end

        NotificationService --> Server: notificationsSent()
    end
end

deactivate NotificationService


== Изменение настроек уведомлений ==

User -> App: Открыть "Настройки уведомлений"
activate App
App -> Server: getNotificationSettings(userId)
activate Server

Server -> DB: loadNotificationSettings(userId)
activate DB
DB --> Server: Текущие настройки (звуки, баннеры, mute-чаты)
deactivate DB

Server --> App: Настройки уведомлений
App --> User: Показать форму настроек

User -> App: Изменить настройки (mute, звук, баннеры)
App -> Server: updateNotificationSettings(userId, settings)

Server -> DB: saveNotificationSettings(userId, settings)
activate DB
DB --> Server: Настройки сохранены
deactivate DB

Server --> App: settingsUpdated()
App --> User: "Настройки уведомлений сохранены"

deactivate Server
deactivate App

@enduml
```
